## 1. Что это и в каком состоянии

React 18 + Vite 5 SPA без бэкенда: crash-игра с обратным отсчётом 5→1, ракетой на
Lottie, взрывом, цветным множителем, ставками и кэш-аутом из виртуального баланса.
Весь стейт — в одном хуке `useCrashRound`. ~1 800 строк, из них примерно половина — CSS.

Сильные стороны:

- **Архитектура соразмерна задаче.** Один хук — вся игровая логика, компоненты чисто
  презентационные. Никакого преждевременного Redux/роутера.
- **Защита от падений продумана лучше, чем в среднем проекте такого размера:**
  `StageErrorBoundary` на корне и на сцене, `LottieAsset` с graceful fallback на
  CSS-ракету, `Preloader` с таймаутом 4 с (не виснет, если ассет 404).
- **Дизайн-система вынесена в токены** (`tokens.css`), тёмная палитра без синего
  отлива, `dvh`, `safe-area-inset`, `prefers-reduced-motion`, мобильный max-width 480px.
- Сборка чистая, предупреждений нет, зависимостей всего 4.

Главный вывод: как **демо/прототип UI** проект в хорошей форме. Как **продукт** он
не готов из-за того, что вся игровая экономика и «честность» живут в браузере
(раздел 2) плюс несколько реальных багов (раздел 3).

## 2. Критично: «провably fair» сейчас ничего не доказывает

`src/utils/fair.js` + `useCrashRound.beginWaiting()`:

```js
const seed = randomSeed();          // генерируется в браузере игрока
const hash = await sha256Hex(seed); // хэшируется там же
crashPointRef.current = crashPointFromHash(hash);
setFair({ hash, seed: null });      // «коммит»
```

Коммит-ревил схема корректна **математически**, но бессмысленна **с точки зрения
доверия**: сервер в схеме не участвует. Хэш публикуется тому же клиенту, который сам
его и сгенерировал — игрок может в DevTools переписать `crashPointRef.current`,
баланс или просто вызвать `cashOut()` на любом множителе. Модалка «Честная игра»
обещает проверяемость, которой нет; для реальных денег это прямой обман пользователя.

Что нужно, если проект идёт в сторону реальных ставок:

1. Раунд генерируется на сервере: `serverSeed` (секрет) + `clientSeed` + `nonce`,
   хэш `serverSeed` публикуется до раунда, раскрывается после.
2. Баланс, ставки и кэш-аут — серверные транзакции; клиент только отображает.
3. Один общий раунд для всех игроков (сейчас у каждого свой) через WebSocket.
4. Юридическая часть: лицензия юрисдикции, age-gate, лимиты, ответственная игра,
   KYC/AML. Сейчас нет ни одного из этих элементов.

Пока это демо — достаточно честно подписать в модалке: «демо-режим, расчёт на
стороне клиента».

### Математика экономики (проверено симуляцией)

Формула `(1 - 0.03) / (1 - r)` работает как заявлено:

| Метрика | Значение |
|---|---|
| RTP при кэш-ауте на x1.5 / x2 / x5 / x10 | 97.3% / 97.7% / 98.9% / 97.8% |
| P(краш ≥ 10x) | 9.7% |
| P(краш ≥ 100x) | 0.96% |
| Средний полёт | 2.8 с |
| Максимум за 200k раундов | **x313 881** (полёт 36 с) |

Два замечания:

- **Нет верхнего кап-лимита.** Примерно 1 раунд из 100 длится дольше 13 секунд,
  1 из 1000 — дольше 20. Для мобильной сессии это мёртвое время. Нужен
  `MAX_MULTIPLIER` (обычно 1000x) и/или нелинейное ускорение роста.
- `Math.round(raw * 100) / 100` округляет **вверх** в половине случаев, то есть при
  кэш-ауте ровно в точку краша игрок иногда выигрывает. Утечка RTP копеечная, но
  правильнее `Math.floor(raw * 100) / 100`.

## 3. Баги

### 3.1 Два параллельных раунда в dev (StrictMode) — реальная гонка

```js
useEffect(() => { beginWaiting(); return clearTimers; }, []);
```

`beginWaiting` — **async** и ставит таймер только после `await sha256Hex(...)`.
В React 18 StrictMode эффект монтируется → размонтируется → монтируется. `clearTimers`
отрабатывает, пока оба вызова ещё висят на `await`; затем оба записывают
`timeoutRef.current`, второй перетирает первый, и первая цепочка отсчёта остаётся
**неотменяемой**. Итог: дёргающийся обратный отсчёт, два `requestAnimationFrame`-цикла,
дубли в истории и удвоение каждые 10 секунд.

Лечение: токен отмены (`let alive = true` / `AbortController`) и проверка его после
каждого `await`, плюс `clearTimers` должен обнулять refs.

### 3.2 Белый экран на HTTP-origin (тест с телефона)

`crypto.subtle` доступен **только в secure context**. Открыть дев-сервер с телефона по
`http://192.168.x.x:5173` → `crypto.subtle` = `undefined` → `beginWaiting` падает
unhandled rejection. Error boundary async-ошибку не ловит, поэтому приложение
навсегда замирает на «5» без единого сообщения. Нужен `try/catch` с
fallback-генератором и видимая ошибка. (Заодно: в `vite.config.js` нет `host: true`,
так что с телефона дев-сервер и не открыть.)

### 3.3 Фоновая вкладка съедает ставку

`requestAnimationFrame` замораживается в скрытой вкладке, но множитель считается от
`performance.now()`. Пользователь сворачивает браузер на 5 секунд — возвращается, и
множитель мгновенно прыгает к точке краша: шанса забрать ставку нет. Нужно либо
ставить игру на паузу по `visibilitychange`, либо авто-кэш-аут, либо честно считать
время по таймеру независимо от rAF.

### 3.4 Неудачная ставка молчит

`placeBet` возвращает `false` при `amount > balance`, но `BetPanel` результат
игнорирует — пользователь жмёт кнопку, ничего не происходит, причины нет.
Кнопка задизейблена по тем же условиям, так что видно это в основном при гонках
фаз, но обработать стоит.

### 3.5 «+» показывает валовую выплату, а не профит

```jsx
Забрано на x{bet.cashedOutAt} · +{(bet.amount * bet.cashedOutAt).toFixed(0)}
```

Ставка уже списана с баланса при её размещении, так что «+200» при ставке 100 и
кэш-ауте x2 — на самом деле «+100» к балансу. Либо убрать «+», либо показывать
`amount * (mult - 1)`.

### 3.6 Цветовые диапазоны расходятся с README

README: «x3.1–10.0 — зелёный». Код: `value <= 3.0 → белый`, то есть x3.05 белый,
а не зелёный. Дыра в спецификации между 3.00 и 3.10 — нужно решить, где граница,
и выровнять код с документацией.

### 3.7 `LottieAsset` не сбрасывает `failed` при смене `src`

Если компонент переиспользуется с другим файлом после неудачи, он навсегда остаётся
на fallback. Сейчас не стреляет (src константные), но мина заложена.

### 3.8 `prefers-reduced-motion` наполовину не работает

CSS-анимации глушатся в `global.css`, но все анимации Framer Motion
(`AnimatePresence`, пружины сцены, отсчёт) продолжают играть. Нужен
`<MotionConfig reducedMotion="user">` на корне.

## 4. Производительность

`setMultiplier` вызывается **каждый кадр** (60 Гц), и так как множитель лежит в
корневом хуке, каждый кадр перерисовывается всё дерево: `LaunchStage` (+ `AnimatePresence`,
`FairnessPanel`, `PingBadge`), `HistoryStrip`, `BetPanel`. На бюджетном Android это
гарантированные просадки именно в самый напряжённый момент игры.

Варианты, по возрастанию усилий:

1. `React.memo` на `LaunchStage`, `HistoryStrip`, `FairnessPanel` (они не зависят от
   множителя) — 10 минут работы, снимает основную часть проблемы.
2. Вынести множитель в отдельный контекст/`useSyncExternalStore`, чтобы
   подписывались только `Multiplier` и строка выплаты.
3. Писать значение прямо в DOM через ref из rAF-цикла, минуя React.

Прочее: бандл 338 kB (103 gzip) — для такого экрана многовато; основной вклад даёт
`@lottiefiles/dotlottie-react` (wasm-плеер) и `framer-motion`. Если анимации простые,
`lottie-web` light-билд или вовсе CSS/SVG (у вас уже написаны качественные fallback'и)
срежут большую часть.

## 5. Честность UI: индикатор PING

`usePing` делает `HEAD /?ping=...` к origin самого приложения. Сервера у игры нет,
так что это задержка до CDN со статикой, а не «пинг до игрового сервера», как это
читается рядом с зелёной точкой. В dev всегда ~1 мс. Либо убрать до появления
бэкенда, либо подписать честно.

## 6. Инфраструктура и гигиена

- **Нет линтера.** В коде есть `// eslint-disable-next-line react-hooks/exhaustive-deps`,
  но ESLint не установлен — комментарии-заглушки без инструмента. Именно
  `exhaustive-deps` и поймал бы баг 3.1.
- **Нет тестов.** Минимум, который окупится сразу: unit на `crashPointFromHash`
  (детерминизм, границы, RTP на фиксированных сидах) и на редьюсер раунда.
- **Нет CI** (`gh` доступен — GitHub Actions на `install → build → lint` ставится за
  один файл).
- **Нет Prettier/EditorConfig**, `engines`/`.nvmrc` не заданы.
- `overrides: { "@rollup/rollup-android-arm64": "4.45.1" }` — костыль под конкретную
  платформу сборки; стоит оставить комментарий, почему.
- README устарел: раздел «Where your animation files go» утверждает, что анимаций нет,
  а `public/animations/rocket.lottie` и `explosion.lottie` уже в репозитории.
- README на английском, интерфейс и `lang="ru"` — на русском. Стоит выбрать одно.
- Нет favicon, `theme-color`, meta description и OG-тегов — для ссылки, которой
  делятся, это заметно.
- Баланс не персистится: F5 = снова 1000.
